# Muza Decors Implementation Plan

> Execution: coordinated parallel implementation for independent storefront and backend tracks; owner integrates admin, hosting, and final verification.

**Goal:** Publish a Kazakh-first Muza Decors storefront on Vercel with authentic work, persistent orders, a protected mobile admin, Excel export and Microsoft Excel Online integration.

**Architecture:** Preserve the original PHP prototype; build the deployable application in `site/`. Next.js handles the storefront and server routes. Neon PostgreSQL stores orders and rate-limit counters; admin sessions use signed cookies. Microsoft Graph can optionally connect a private workbook after business-owner authorization.

**Tech Stack:** Next.js, TypeScript, React, PostgreSQL, Zod, ExcelJS, npm.

## Constraints and source facts
- Instagram confirms Oral/Uralsk, +77074528842, events, neon, 3D letters and canvases. Real locally saved Instagram imagery only; retain post source links.
- No invented prices, reviews, completion counts, or delivery promises.
- Preserve original order fields (phone, sign text, event, color, details). Support Kazakh Unicode.
- Customer registration is unnecessary for a quote request.
- Shipping: pickup, Oral local delivery, or manually arranged Kazpost to another Kazakhstan city. Require recipient name, phone, region, city, street/address and postcode for Kazpost; apartment is optional. Price confirmed separately; admin records tracking.
- Do not pretend Excel is connected without real Microsoft authorization.

## Shared contract
POST `/api/orders`: `{name,phone,service,event,eventDate,signText,color,details,deliveryMethod,recipientName,recipientPhone,region,city,address,apartment,postalCode,consent,website,idempotencyKey}`. Required base: name, phone, service, consent. deliveryMethod: pickup|oral|kazpost. Optional strings default empty. Returns `{id,reference}` on success; `{error}` on failure.
Services: event, neon, lettering, canvas. Order statuses: new, contacted, confirmed, production, ready, shipped, completed, cancelled.
GET `/api/admin/orders` -> `{orders}`; PATCH `/api/admin/orders/[id]` accepts `{status,adminNotes,shippingCost,trackingNumber}`. Amount is nonnegative KZT or null.
POST `/api/admin/login` accepts `{password}`; POST logout; GET session returns `{authenticated}`. Cookie session. Protected GET `/api/admin/export` exports XLSX.
Order persisted shape: input fields plus id, reference, status, adminNotes, shippingCost, trackingNumber, createdAt, updatedAt.

The user requested no external account sign-in and confirmed both PC and phone management. The default workflow is now private browser administration plus account-free XLSX download/upload. OneDrive remains optional and is not connected. Manual imports only edit approved administrator fields, reject stale versions atomically, and never insert or delete orders.

Completed: storefront, private admin, live Neon persistence, Kazpost address collection, manual XLSX round-trip, Kazakh instructions, Vercel production publication. Verified: 38/38 tests (including live database and import atomicity), TypeScript production build, zero production dependency audit findings, desktop/mobile browser flow and axe checks. Optional live Microsoft OAuth was intentionally not completed after the user requested the account-free workflow.
